# ระบบขายหน้าร้าน ดอยเมฆ (สำนักงานใหญ่ + สาขาแฟรนไชส์)

- สำนักงานใหญ่: ล็อกอินเห็นทุกสาขา สร้าง/ระงับสาขา ออกบัญชีเจ้าของ แก้เมนูกลางครั้งเดียวทุกสาขาเปลี่ยนพร้อมกัน ตั้งราคาเฉพาะสาขา ดูยอดขายรวม/แยกสาขา โหลด CSV
- สาขา (เจ้าของแฟรนไชส์ แต่ละสาขาแยกเจ้าของ): ล็อกอินด้วยอีเมล/รหัสผ่าน ขาย ดูออเดอร์ ยกเลิกออเดอร์ ดูสรุปยอด กดเมนูหมด เห็นเฉพาะข้อมูลสาขาตัวเอง
- เลขออเดอร์แยกสาขา เริ่ม 1 ใหม่ทุกวัน (เวลาไทย) · ราคาคำนวณที่เซิร์ฟเวอร์ · กดชำระซ้ำตอนเน็ตหลุดไม่เกิดออเดอร์ซ้ำ
- อัปเดตโค้ดครั้งเดียว ทุกสาขาโหลดเวอร์ชันใหม่เองภายใน ~1 นาที (ถ้ากำลังมีตะกร้าค้างจะขึ้นแถบให้กดอัปเดตหลังชำระเงิน)

## ขึ้นระบบบน Railway (ประมาณ 15 นาที)

1. สมัคร GitHub แล้วสร้าง repository ใหม่ (Private) อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ (ยกเว้นโฟลเดอร์ `data`)
2. สมัคร https://railway.com → New Project → Deploy from GitHub repo → เลือก repo นี้
3. เข้า service → แท็บ **Variables** ใส่
   - `ADMIN_EMAIL` = อีเมลของคุณ (ใช้ล็อกอินสำนักงานใหญ่)
   - `ADMIN_PASSWORD` = รหัสผ่านที่คุณตั้ง (อย่างน้อย 8 ตัวอักษร ยาวๆ เดายาก)
   - `DATA_DIR` = `/data`
   - `SHOP_NAME` = ชื่อร้าน (ไม่บังคับ)
4. แท็บ **Settings → Volumes → New Volume** ตั้ง Mount path = `/data` **(สำคัญมาก ถ้าไม่ทำ ข้อมูลหายทุกครั้งที่ deploy)**
5. Settings → Networking → **Generate Domain** จะได้ลิงก์ เช่น `https://xxxx.up.railway.app` (ผูกโดเมนตัวเองทีหลังได้)
6. เปิดลิงก์ ล็อกอินด้วย ADMIN_EMAIL/ADMIN_PASSWORD → แท็บ "สาขา" → "+ เพิ่มสาขา" → ระบบแสดงรหัสผ่านชั่วคราวครั้งเดียว ส่งให้เจ้าของสาขา
7. ครั้งแรกระบบใส่เมนูตัวอย่าง 13 รายการให้ แก้ในแท็บ "เมนูกลาง" (ไม่อยากได้เมนูตัวอย่างตั้ง `SEED_MENU=0` ก่อน deploy ครั้งแรก)

อัปเดตระบบภายหลัง: แก้ไฟล์ใน GitHub (หรือ push) → Railway deploy ให้เอง → ทุกสาขาได้เวอร์ชันใหม่

## สำรองข้อมูล
ข้อมูลทั้งหมดอยู่ในไฟล์ `/data/pos.db` บน Volume ควรกด Backup ใน Railway Volume เป็นระยะ และให้สาขาโหลด CSV ยอดขายสิ้นเดือน

## รันทดสอบในเครื่อง
ต้องมี Node 22.13 ขึ้นไป: `npm test` (ทดสอบ API) · `npm start` แล้วเปิด http://localhost:3000

## ข้อจำกัดที่ควรรู้
- ต้องมีอินเทอร์เน็ตตอนขาย (ยังไม่มีโหมดออฟไลน์) · ยังไม่ต่อเครื่องพิมพ์ใบเสร็จ (คัดลอกข้อความได้)
- 1 สาขา = 1 บัญชี (เจ้าของแชร์ให้พนักงาน) ถ้าต้องการบัญชีพนักงานแยกต้องเพิ่มฟีเจอร์
- ฐานข้อมูล SQLite เหมาะกับ 10–30 สาขา ถ้าขยายถึง 100 สาขาควรย้ายไป Postgres
- ตัวเลือกเครื่องดื่ม (ร้อน/เย็น/ปั่น, ความหวาน, ท็อปปิ้ง) แก้ที่ค่าคงที่ `OPT` ใน `server.js`
